# ADB Screenshot

Android 지도 화면을 캡처해 시각, 경로 거리, 예상 소요시간, 통행료와 도착 예정시간을 확인하고 엑셀로 저장하는 PC용 프로그램입니다. 출발·목적지 좌표, 별도로 조회한 추천 경로와 실제 이동 GPS도 기록합니다. 전체 설계는 [설계.md](설계.md)를 참고하세요.

## Mac용 앱 다운로드

Apple Silicon Mac(macOS 26 이상)에서는 [최신 릴리스](https://github.com/GuruNet/ADB_Screenshot/releases/latest)에서 macOS용 ZIP을 다운로드하세요. [1.0.0 앱 ZIP 바로 다운로드](https://github.com/GuruNet/ADB_Screenshot/releases/download/v1.0.0/ADB-Screenshot-1.0.0-macOS-arm64.zip)

압축을 풀고 `ADB Screenshot.app`을 응용 프로그램 폴더로 옮기세요. 기기 연결에는 [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools)의 ADB가 필요합니다. Python과 문자 인식 도구는 앱에 포함되어 있습니다. 이 빌드는 Apple 공증을 받지 않아 처음 실행할 때 macOS가 열기를 제한할 수 있습니다.

## 소스 실행 준비

1. Python 3 및 Tkinter를 설치합니다. macOS에서는 Tkinter가 포함된 Python이 필요합니다.
2. [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools)를 설치하고 `adb`를 명령줄에서 실행할 수 있게 설정합니다. 일반적인 Android SDK 설치 위치도 자동으로 확인합니다.
3. Android 기기에서 개발자 옵션을 켜고, USB 디버깅 또는 무선 디버깅을 활성화합니다.
4. 문자 인식에는 macOS의 Swift와 한국어 지원 Apple Vision이 필요합니다. 다른 운영체제에서는 Tesseract OCR과 한국어(`kor`)·영어(`eng`) 언어 데이터를 설치하고 `tesseract`를 PATH에 추가하세요. OCR을 사용할 수 없어도 수동 입력은 가능합니다. 사진 미리보기는 Pillow가 있으면 창 크기에 맞게 부드럽게 조정되며, 설치되지 않으면 기본 축소 방식으로 표시됩니다.
5. 엑셀 저장을 위해 프로젝트 가상환경에 의존성을 설치합니다.

   ```bash
   python3 -m venv .venv
   .venv/bin/python -m pip install -r requirements.txt
   ```

   Windows는 `py -m venv .venv`와 `.venv\Scripts\python.exe -m pip install -r requirements.txt`를 사용하세요.

## 실행

macOS에서는 이 폴더의 `실행.command`를 두 번 클릭해 실행할 수 있습니다. 터미널 또는 명령 프롬프트에서 이 폴더로 이동한 후 다음 명령으로 실행해도 됩니다.

```bash
.venv/bin/python app.py
```

Windows에서는 `.venv\Scripts\python.exe app.py`를 사용하세요. macOS의 `실행.command`는 `.venv`가 있으면 자동으로 사용합니다.

## macOS 앱 빌드

현재 빌드 환경은 Apple Silicon 및 macOS 26 이상입니다. Xcode Command Line Tools가 설치된 Mac에서 다음 명령으로 앱을 만들 수 있습니다.

```bash
.venv/bin/python -m pip install -r requirements-build.txt
./build_app.sh
```

결과는 `dist/ADB Screenshot.app`입니다. Finder에서 두 번 클릭해 실행할 수 있고 Python을 따로 실행할 필요가 없습니다. 문자 인식 실행 도구와 GPS 보조 APK가 포함됩니다. Android SDK Platform-Tools의 ADB는 별도로 설치되어 있어야 하며, 앱은 일반적인 SDK 경로와 Homebrew 설치 경로도 확인합니다.

터미널에서는 `open "dist/ADB Screenshot.app"`으로 엽니다. 이미 실행 중이면 기존 창이 활성화됩니다. 다시 빌드한 버전을 시험할 때는 기존 창에서 수정한 내용을 저장하고 창을 닫은 뒤 같은 명령으로 여세요.

## 사용 방법

개발자 옵션이 보이지 않는다면 일반적으로 휴대폰 설정에서 **빌드 번호**를 일곱 번 누르면 활성화됩니다. 빌드 번호의 위치와 메뉴 이름은 기기에 따라 다릅니다.

1. 연결 방법 중 하나를 사용합니다.
   - **USB:** 데이터 통신을 지원하는 케이블로 Android 휴대폰을 PC에 연결합니다. 휴대폰의 개발자 옵션에서 USB 디버깅을 켜고, 기기에 디버깅 허용 메시지가 나타나면 허용합니다. 프로그램에서 **기기 목록 새로고침**을 눌러 휴대폰을 선택합니다. USB 연결 시 IP 주소는 입력하지 않아도 됩니다.
   - **무선:** Android의 무선 디버깅 화면에서 기기의 IP 주소와 **연결 포트**를 확인해 입력합니다. 최초 페어링이 필요하면 기기의 **페어링 코드로 기기 페어링** 화면에서 별도의 페어링 포트와 6자리 코드를 확인하고 입력한 뒤 **페어링**을 누릅니다. 페어링 후 연결 포트로 **연결**을 누르고 기기를 선택합니다. 기기와 Android 버전에 따라 초기 USB 설정이 필요한 경우도 있습니다.
     휴대폰에 주소가 `IP:포트` 형태로 표시되면 프로그램의 IP 주소 칸에 전체를 붙여 넣어도 됩니다. 버튼을 누르면 그 작업에 사용하는 포트 칸에 자동으로 분리됩니다. 페어링 포트와 연결 포트는 각각 확인하세요.
   - **자동 찾기:** 연결 설정에서 **자동 찾기**를 누르면 네트워크에 광고된 무선 디버깅 후보가 표시됩니다. 현재 USB 기기와 일치하는 하나의 연결 후보가 이미 페어링되어 있다면 동일 기기 확인 후 자동으로 연결·선택합니다. 최초 페어링 코드는 휴대폰에서 확인해 직접 입력해야 합니다. 후보가 여러 개거나 일치 여부를 확인할 수 없으면 직접 선택·연결합니다.
     휴대폰이 핫스팟을 제공하고 노트북이 그 핫스팟에 연결된 상태에서도 자동 발견을 시도할 수 있습니다. 실제 연결 기기에서 이 구성을 시험했지만, 당시 휴대폰의 Wi-Fi도 동시에 켜져 있었습니다. 무선 디버깅 가능 여부와 mDNS 발견은 기기·네트워크에 따라 달라지므로, 검색이 안 되면 재검색하거나 IP·포트를 직접 입력하세요.
2. 기기에서 티맵, 네이버 지도 또는 카카오맵을 열고 출발 화면을 준비합니다. 프로그램에서 **앱 확인**을 눌러 현재 앱을 확인할 수 있습니다.
3. 가운데 **화면 비교 → 출발 화면** 영역에서 **출발 화면 캡처**를 누릅니다. 출발 이미지와 여정 정보가 먼저 저장됩니다. **GPS 기록 함께 시작**이 선택됐다면 휴대폰의 보조 앱에서 기록 시작을 승인한 뒤 지도 앱으로 돌아갑니다. 필요하면 **GPS 상태 확인**으로 승인·수신 상태를 새로 확인합니다.
4. 도착했을 때 지도 앱의 도착 화면을 준비하고 가운데 **화면 비교 → 도착 화면** 영역에서 **도착 캡처 및 종료**를 누릅니다. 도착 화면을 먼저 저장한 후 GPS를 종료·동기화합니다. 도착 감지는 자동이 아니며 사용자가 버튼을 누릅니다.
5. **출발 보기** 또는 **도착 보기**를 눌러 각 화면과 인식값을 따로 확인하고, 필요하면 수정한 뒤 **검토 완료 및 저장**을 누릅니다. 오른쪽 **인식 결과 검토**에서 출발·도착을 선택할 수 있습니다. 가운데 **스크린샷** 탭에서 선택 화면을 크게 보고 **원본 크게 보기**로 원본을 스크롤할 수 있습니다.
6. **GPS·엑셀**을 누르면 여정에 연결된 좌표, 실제 이동 기록 및 엑셀 저장 화면이 열립니다. 출발·도착을 구분할 필요가 없는 화면은 가운데 상단의 **단일 캡처**로 저장할 수 있습니다.

출발과 도착은 별도의 `_start.png`, `_finish.png`와 하나의 `_start.json`으로 묶입니다. 프로그램을 다시 실행하면 진행 중인 여정을 자동으로 복원합니다. 파일을 이동했거나 자동 복원되지 않으면 **기존 캡처 열기**에서 출발 PNG 또는 JSON을 선택하세요. PC 프로그램을 닫아도 휴대폰 GPS 보조 앱의 기록은 자동 종료되지 않습니다. 도착 이미지가 저장된 후 GPS 동기화가 실패하면 이미지는 유지되며 **종료 재시도**를 사용할 수 있습니다. 출발과 도착에서 다른 앱이 보였거나 앱을 식별하지 못한 경우 화면에 확인 상태가 표시됩니다.

### 출발지·목적지 및 추천 경로

- 위도·경도를 직접 입력해 저장하거나, 지도사 공식 검색 API의 후보에서 장소를 선택할 수 있습니다. 네이버 검색은 주소를 기준으로 합니다.
- 실제 이동 기록을 동기화했다면 **이동 기록 처음·끝 사용**으로 첫 위치와 마지막 위치를 입력할 수 있습니다. 이는 실제 측정 지점으로, 지도 앱에서 지정한 출발·목적지와 차이가 있을 수 있습니다.
- 자동차 추천 경로는 선택한 서비스의 공식 API로 **별도로 다시 계산**합니다. 화면에 보이는 경로의 원본 좌표를 스크린샷에서 추출하는 기능은 아니며, 교통 상황·옵션·조회 시각 등에 따라 화면과 다를 수 있습니다. 출처와 화면 일치 미확인 상태를 함께 저장합니다.
- TMAP과 카카오에는 각 서비스 API 키, 네이버에는 Client ID와 Client Secret이 필요합니다. 길찾기 및 장소 검색 상품이 각각 활성화되어야 할 수 있으며 이용 조건과 비용은 각 서비스에서 확인하세요. 입력한 키는 메모리에만 보관하고 캡처 파일이나 엑셀에 저장하지 않습니다. 검색어 및 좌표는 해당 지도사로 전송됩니다.
- 공식 안내: [TMAP 경로안내](https://tmap-skopenapi.readme.io/reference/%EC%9E%90%EB%8F%99%EC%B0%A8-%EA%B2%BD%EB%A1%9C%EC%95%88%EB%82%B4), [네이버 Maps Directions](https://api.ncloud-docs.com/docs/application-maps-directions5), [카카오모빌리티 길찾기](https://developers.kakaomobility.com/guide/navi-api/directions), [카카오 장소 검색](https://developers.kakao.com/docs/ko/local/dev-guide).

### 실제 이동 GPS

1. 최초 사용 시 **GPS·엑셀 → 실제 이동 GPS** 탭에서 **휴대폰 보조 앱 설치**를 누릅니다. Android 8 이상이 필요하며 기존 지도 앱을 변경하지 않습니다.
2. 메인 화면의 **GPS 기록 함께 시작**을 선택한 상태로 출발 화면을 캡처하거나, **실제 이동 GPS** 탭에서 별도로 **GPS 기록 요청**을 누릅니다. 휴대폰의 보조 앱에서 **GPS 기록 시작**을 누르고 정확한 위치 및 필요한 알림 권한을 허용합니다.
3. 휴대폰에서 지도 앱으로 돌아가 이동합니다. GPS 기록 중 휴대폰에 지속 알림이 표시됩니다. 실내에서는 GPS 위치가 바로 수신되지 않을 수 있습니다.
4. 메인 화면의 **GPS 상태 확인** 또는 탭의 **기록 상태 확인·동기화**로 기록을 PC에 저장합니다. 도착 화면 캡처 시 종료·동기화하며, 탭의 **기록 중지 및 동기화**로 별도 종료할 수도 있습니다. PC 연결이 끊겨도 보조 앱이 실행 중이면 휴대폰에 기록되며, 다시 연결한 뒤 동기화할 수 있습니다. 휴대폰의 보조 앱에서도 기록을 중지할 수 있습니다.
5. 한 캡처에는 하나의 이동 기록을 연결합니다. 별도 기록은 새 캡처에서 시작합니다. 기기에서 GPS가 꺼지거나 권한이 거부되면 해당 상태가 표시됩니다.

휴대폰 보조 앱을 삭제하면 휴대폰에만 남아 있는 기록도 삭제되므로 필요한 기록을 먼저 PC에 동기화하세요. PC에 저장된 PNG·JSON·엑셀 파일은 별도로 관리합니다.

### 통행료와 도착 예정시간

출발 화면의 **예상 통행료**는 선택한 경로에 표시된 요금입니다. ‘통행료 없음’은 **0원**으로 표시하고, 요금을 판별할 수 없는 경우 입력란을 비워 둡니다. 검토 화면에서 금액을 수정할 수 있으며, 엑셀의 **예상 통행료** 열에도 반영됩니다.

출발 화면의 **도착 예정시간** 입력란에는 **화면 표시 시간 + 예상 소요시간**이 자동으로 들어갑니다. 예를 들어 22:12에 35분을 더하면 22:47입니다. 예정시간을 직접 입력한 뒤 **검토 완료 및 저장**을 누르면 수정한 시간이 미리보기와 엑셀에도 반영됩니다. 자동 계산으로 돌아가려면 예정시간을 지우고 입력란을 나가세요.

도착 화면에서는 **주행거리**, **소요시간**, **실 통행료**를 확인하고 수정할 수 있습니다. 금액을 읽을 수 없으면 입력란에 **없음**이 표시됩니다. 확인한 금액을 직접 입력해 저장할 수 있습니다. 출발 화면의 예상 통행료는 별도로 보관합니다.

### 엑셀 내보내기

**엑셀 내보내기** 탭에서 현재 여정 또는 선택한 여러 기록을 `.xlsx`로 저장합니다. 출발·도착 화면의 시각과 인식 결과, 출발·목적지, 추천 경로 좌표, 실제 이동 궤적을 담습니다. 실제 이동 기록은 최신 상태로 **동기화**한 뒤 내보내세요.

메인 화면 하단의 **수집 기록**는 저장 폴더의 모든 캡처와 다른 폴더에서 현재 열어 둔 기록을 실제 엑셀과 같은 시트 구조로 보여 줍니다. 시트를 고르고 검색하거나 **표시 항목**에서 보고 싶은 열을 선택할 수 있습니다. 검색은 숨긴 열을 포함한 전체 열에서 수행합니다. 인식값을 수정 중이면 저장한 뒤 표와 내보내기에 반영됩니다.

- **전체 내보내기:** 검색과 표시 항목에 관계없이 수집 기록 전체를 네 개 시트로 저장합니다.
- **선택 내보내기:** 현재 시트에서 검색 조건에 맞는 모든 행과 표시 중인 열만 저장합니다. 선택 내보내기 파일에는 현재 시트 하나가 들어갑니다.

미리보기는 최대 500행을 표시하지만 검색은 전체 데이터에서 이루어지며, 내보내기에는 500행 이후의 일치 항목도 포함됩니다.

정보 파일에는 캡처 시각, 기기 식별자, 캡처 전후 앱 정보, OCR 원문·추정값 및 검토한 값이 포함됩니다. 화면 표시 시간은 PC의 캡처 시각과 별도로 저장합니다. OCR 결과가 없거나 후보가 여러 개면 빈칸으로 표시할 수 있으며, 인식값은 항상 원본과 비교해 확인하세요. 캡처 전후에 앱이 바뀌거나 판별이 실패하면 앱 식별이 불확실한 것으로 저장됩니다. 스크린샷과 정보 파일에는 개인 정보가 포함될 수 있으므로 보관 위치에 유의하세요.

## 현재 범위

실제 이동 기록은 휴대폰이 제공한 GPS 측정값입니다. API로 재계산한 추천 경로 및 지도 화면에 그려진 경로와는 구분됩니다. 캡처 이미지와 좌표는 민감한 위치 정보를 포함할 수 있으므로 보관·공유 시 유의하세요.

기기 목록이 비어 있으면 USB 케이블과 디버깅 승인 상태를 확인하세요. 무선 연결이라면 무선 디버깅과 네트워크, 주소 및 연결 포트도 확인하세요. `unauthorized`로 표시되는 기기는 Android 화면의 디버깅 승인 요청을 확인해야 합니다. 현재 앱이 인식되지 않으면 지도 앱을 전면에 띄운 후 다시 확인하세요.
